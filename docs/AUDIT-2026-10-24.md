## Changes implemented

- Customer recovery no longer requires re-entering an email, keeps the password editor visible during recovery, and preserves the completion message. Login accepts existing passwords without applying the new-account minimum-length rule.
- Added signup-confirmation resend with email validation, error handling and duplicate-click guard. This is real Supabase Auth code, but delivery requires a live mailbox test.
- Added admin recovery entry point using the same customer-site recovery handler. Admin permission checks remain separate from signup.
- Removed duplicate Supabase SDK loading. No private/service-role key was introduced.
- Catalog now reads stock and disables purchase of stock-zero items; a successful empty catalog no longer resurrects static products. Failed child-data loading preserves the last usable catalog instead of replacing sizes/images with empties. Independent metadata errors no longer discard other successful section reads. Empty slider/feedback datasets are respected.
- Checkout prevents concurrent submissions, no longer requests private order SELECT after INSERT, retains the cart on persistence failure, and explicitly distinguishes database failure from the manual WhatsApp route. Guest database persistence is still blocked by the server, as documented above. Server-side total validation/idempotency remain unverified.
- Product edits preserve unchanged child IDs and metadata. New child values are inserted before obsolete values are removed; broad delete-and-recreate and destructive rollback were removed. A failed new-product detail save requires reopening that product rather than silently creating duplicates. This is safer but is NOT a database transaction: cross-table partial updates still require a reviewed server-side transactional function once schema access exists.
- Product deletion relies on the database operation and its constraints, instead of deleting children first. FK behavior must be verified with admin access before declaring deletion fully functional.
- Fixed re-enabling an out-of-stock product, negative/invalid price validation, detection of zero-row product updates, admin login button state, logout error reporting and keyboard access behind the login gate. The gate is UX defense, not a replacement for RLS.
- Added a feedback management section backed by the existing `feedback` table and `product-images` bucket: list, add/edit, show/hide, ordered records, and JPG/PNG/WebP upload with size checks. Live privileged writes/uploads are not verified.
- ELYRA now has a 30-second abort timeout, offline handling, duplicate-send guard, bounded successful-turn history, input restoration after failure, and explicit disclosure of FAQ-only backend mode. No uninspected Edge Function was replaced.
